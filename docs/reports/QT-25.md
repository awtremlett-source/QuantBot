## Part C — the false NOT CLEAN on the first run after switch-on (25db63a)

### C1. Diagnosis

- **Which check fires.** `clean_step.run` judges both censuses strictly:
  - the 5m census's newest London bar is held against the newest London session that has closed
    (16:30 UK);
  - "5m LSE clean bars end D−1, but the D session has finished" becomes a complaint, and
    record_now prints RUN NOT CLEAN (exit 1).
- **The catch-up schedule.** Only `record_now`'s catch-up fetches 5-minute bars (the hourly run
  fetches 1-minute bars). It runs when `should_catch_up` holds: **both markets shut** (each
  exchange's own calendar) **or** the day's last trigger (**20:00 by the PC's clock**, which is UK
  local time).
- **Which clock.** The 20:00 is UK local time; "both shut" uses the exchange clocks.
  - **This week** (UK on GMT, New York on summer time) New York closes at 20:00 UK, so both ways
    meet at 20:00 UK.
  - In a normal week the 20:00 UK trigger comes first (New York closes at 21:00 UK).
  - On a US-only holiday London's 16:30 close is enough.
- **Why the false RED.** The first run after the PC wakes (18:08–18:21 UK) is due to clean, but
  that day's 5-minute bars are fetched only at 20:00.

### C2–C3. Test and fix

- **Tests** (tests/qb2/test_qt25_not_yet_due.py):
  - before the day's catch-up is due, its 5-minute bars are **NOT YET DUE** (shown, not RED);
  - once due and still missing, RED as now;
  - an older missing day is RED at any hour;
  - the due time: Fri 23 Oct 20:00 UK, Mon 26 Oct 20:00 UK, Thanksgiving (26 Nov) 16:30 UK;
  - Monday 19:59 vs 20:00 UK;
  - record_now's catch-up hour equals the triggers' last hour. RED first on the old code (in the
    same record).
- **Fix: when the check judges, nothing else.**
  - `run_times.catchup_due(day)` is min(the day's last trigger, the later exchange close that day).
  - `clean_step.expected_session(..., interval="5m")` counts a day only once that time has passed.
  - The Clean store line shows, for example, "· 5m LSE 2026-10-23: NOT YET DUE (its catch-up runs
    from 20:00 UK)".
  - No gate (95%, 50%), no 10:00 overdue rule, no 1-minute rule, and no scheduled task changed.
- **Mutant** (due time ignored): RED, restored, sha256 checked.
- **Gate C replay:** Wed 21 18:21, Thu 22 18:14 and Fri 23 18:08, each with the newest bars its log
