## Part C — when London's closes arrive: a measurement only (PROPOSE 1)

### C1. What was built

- **`qb2/data/arrival.py` (new, 129 lines).** Every recorder run, after the daily top-up, appends ONE line to
  `data/clean/arrival.jsonl`: for London and the US (a session counts once any of the market's names holds it, the same
  rule as behind.py) and for VWRL.L and VWRP.L, the newest finished session the daily step wants and its state:
  **present** (the store holds its close) · **blank** (this run's fetch sent the session with no close) · **refused**
  (sent with a close, but the door refused it) · **absent** (this run's fetch did not send that session) · **not
  fetched** (nothing was fetched for it this run). A market not present also counts its names by what each sent.
- **How it sees "blank" vs "absent":** the daily step's fetch is passed through a `Watch` that notes the last 5 rows of
  each name it fetches and **returns the very same frame** (a test checks it is the same object). No extra fetch, no
  extra call to Yahoo.
- **`qb2/data/daily_step.py` (238 → 239 of 250 lines):** the watch around the fetch, and the note after the line. A
  failed write is added to the "Daily store:" line ("arrival log not written …") and changes nothing else (a test runs
  a top-up with the log unwritable and compares its marker with a twin's).
- **Nothing reads the log but people:** a test parses every qb2 module and allows only daily_step to import arrival, and
  no other module to name the file. **No schedule change.**
- Size: one line of 273 bytes a run when all is present (about 330 with a market's counts), 14 runs a weekday: about
  1 MB a year.
