| `qb2/data/earnings_step.py` | reads **its own** marker (earnings_step.json) | not affected, **not changed** (box rule) |

**What the map decided.** Every live reader comes through `live.final_through`, which reads `fetched_through`. So the
fix is in the one writer: `fetched_through` now means "final for every market and both stop-driving names", held back
before the oldest missing session; the daily step's own "has the whole list been fetched for this day" moves to a new
key, `topped_up`. **No reader was changed.** A marker without the new keys reads exactly as before.

### C1 — what was built

- **`qb2/data/behind.py` (new, 125 lines, pure).** For each market (London, US: all its names together) and each name,
  the sessions of its own exchange calendar it lacks, from the stop path's last floor (or its newest stored session, or
  the session it was already recorded on, whichever is earliest) up to the market's newest session on or before the
  top-up's day. So a holiday is never missing.
  - A market, or VWRL.L / VWRP.L, that lacks one is **BEHIND**: in the marker by name and session with when it was first
    seen (a), retried every run (b), RED in the line every run, strict or not (c), and `fetched_through` is held on the
    London session before its oldest missing one (d). When a later session has arrived, the line says **"gap: <name>
    <date> never delivered"** (f). Nothing ever fills it.
  - Any other name lacking a session its market has is **short**: named in the line, retried, never holding the stops
    (premortem 9). ^VIX keeps its QT-24/QT-29 rules and is not judged here.
- **`qb2/data/daily_step.py` (196 → 238 lines, under 250).** Retries `lost` plus every name the scan found lacking, at
  most once a run (b); records the retry's time (`retry_s`) and shows it while anything is still missing; keeps the
  day's notes (kept / corrected / refused) across retries; writes the marker **whole or not at all** (a `.part` file,
  then a rename: premortem 6); on a marker from before QT-32 it looks at the store before trusting it (premortem 10);
  reads the store once a run (the old `newest_by_market` re-read every file: that duplicate read is gone).
- **e) exactly once, in order: the existing catch-up already does it**, once `fetched_through` never passes a missing
  close. The advisor and the bot pot process each unwritten session oldest first and never re-do a written one; P22's
  journal writes one line per name and session; Trading 212's price for Monday is the one read between Monday's close
  and Tuesday's open, so a late session still finds it. **Not rebuilt: proved by two end-to-end tests** (below).
- **What changes for QT-26 C (the SKIPPED row).** A stop-driving close that is missing now holds the stop path instead

### D2. What was built

- **`python -m qb2.tools.record_split --instrument CSH2l_EQ [--words "…"]`** (`qb2/tools/record_split.py`, new).
  Reads with the read-only client only and imports no order client (a test reads its imports). Takes only the
  instrument's FILLED bookings with fill type STOCK_SPLIT, signed the right way, whose order id the ledger lacks; **any
  other booking the ledger lacks refuses the whole run**. One SPLIT line per broker order id, oldest id first;
